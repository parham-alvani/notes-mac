## Introduction

Daftar is a native macOS app for an [Obsidian](https://obsidian.md) vault that is kept in a Git repository. It is the Mac part of [Daftar for Android](https://github.com/parham-alvani/notes-droid), and it uses the same colors (the naz palette on dark, Daylight on light) and the same rules for links, tasks and the calendar week notes.

The aim is to replace Obsidian on the Mac. It has the reader, the daily tool and the editor; the Neovim mode comes next.

## Features

- **Reader:** Obsidian's markdown with wikilinks, embeds, callouts, highlights, tags, footnotes, math (KaTeX), Mermaid diagrams and colored code. Each paragraph takes its own direction, so Persian text reads right to left with no plugin. Callouts have their icons, each tag has its own color, `==🔴 text==` and the other five circles color a highlight as in Obsidian, task dates and priorities are colored chips, a code block shows its language and a copy button, and a thin bar at the top shows how far you have read. Videos, sounds and PDFs play in the note.
- **Reading cursor:** the reader marks the paragraph you read, and in a paragraph of many lines a band marks the line, so a long paragraph does not lose your place. `j` and `k` or the arrows go a line at a time and on to the next paragraph, `g` and `G` go to the ends, `[` and `]` go to the headings, and a click puts it on the line you click. In Persian the bar is on the right. When you scroll away, it comes to the first line on screen. ⌘E opens the editor on that line, and the reader comes back to the editor's line when you close it. `appearance.reading_line` sets the band's strength in percent (18 at first); 0 leaves it out.
- **Text width:** `appearance.text_width` is the widest line of text in the reader and the editor, in em of the text size: 46 at first (about 95 letters in SF Pro at size 14), 0 for the whole window. A narrow pane (a split, a small window, under 720 points) keeps 16 points on each side instead of 32 to 35.
- **Find:** ⌘F finds in the note, in the reader and in the editor. ⌘G and ⇧⌘G go to the next and the previous match.
- **Editor:** ⌘E opens the note's markdown, styled as you type in the same colors as the reader, with the cursor's line lit and the words and characters counted in the bar under it. It saves a second after you stop typing. It shows embedded images, completes `[[` links from the vault's notes and their aliases, `[[Note#` from the note's headings, `[[Note#^` from its paragraphs and list items, and `#` tags from the vault's tags, continues lists on Return, moves list items by four spaces with Tab, ticks a task with ⌘↩, and saves a pasted image to the attachment folder.
- **Properties:** in the editor, the front matter is a form above the text, as Obsidian's Properties view: a text or number field, a checkbox, a date or a date and time picker, and chips for a list, tags in their colors. The type comes from `.obsidian/types.json`, or else from the value. Add a property (its name is completed from the names in the vault), rename it or remove it. A change writes only the lines of that property, in their own style (quotes, `[a, b]` or `- a` lists), and never the body. Front matter that the form cannot show without a change (comments, anchors, a map in a map, text on more than one line) stays as YAML, and a line above it says why. "Show Source" (`editor.properties_form`) shows the YAML.
- **Neovim mode:** a setting that makes your own Neovim the editor. Neovim owns the buffer and writes the file, with your `init.lua`, motions, macros and plugins; the editor shows it with its colors, images and right-to-left text, a block cursor in Normal mode in the text's color with the letter under it in the background's color (as Neovim's own reverse video, so it is not like the colors of code or markup), and a bar with the mode and the command line.
- **Task queries:** ` ```tasks ` blocks show their tasks, grouped and sorted as the Tasks plugin does, with a checkbox that ticks the task in its own note. A line the app cannot read is shown above the result.
- **Persian:** each block takes the direction of the text it shows, not of its syntax, so `- [x] تماس` and `[[Note|یادداشت]]` read right to left in the reader and stand on the right in the editor; a list, a quote and a table put their marks on the side their first item reads from, and a date in a Persian line keeps its order (`2026-10-30`, never `30-10-2026`). Search and quick open find a word however it was typed: `ي` or `ی`, `ك` or `ک`, `۱۲` or `12`, and `می‌خواهم` with the half space, a space or none. In Neovim mode, Normal mode's keys work with the Persian layout on (`langmap`, from the keyboard's layouts, unless your config sets one), while Insert mode types Persian.
- **Fonts:** New York for notes and JetBrains Mono for code by default, both settings, with Vazirmatn for Persian.
- **Sidebar:** the folder tree with folder notes, full-text search (SQLite FTS5) in the system search field (⇧⌘F), and `#tag` search. A note with the words side by side, as typed, comes first, then one with the words near each other, then one with them anywhere.
- **Search by meaning:** under the words, the sidebar's search lists the notes it finds **by meaning**: notes that say the same thing in other words, in Persian or English, from the model of `daftar-cli` (0.23.0 or later), which runs on this Mac and asks no server. The inspector lists the open note's **related notes**, which are near it in meaning but not linked from it yet. The model (531 MB) is downloaded once, when you click "Download the model"; the download and the first index show their progress and can be cancelled. After the vault changes, the index reads the changed notes again in the background, 10 minutes after the last change (`meaning.refresh_minutes`). `meaning.search = false` turns both off.
- **Bases:** a `.base` file opens as its views, with a tab for each: the filters, formulas, sort, `groupBy` and `limit` of Obsidian Bases, with the same expression language (`file.*`, `formula.*`, dates and durations, `if()`, string and list methods). `![[x.base]]`, `![[x.base#View]]` and ` ```base ` blocks show a base inside a note. A `table` view is a table. A `cards` view is a grid of cards: each card has the note's name, the cover from the view's `image` property (a picture in the vault, a web address or a `#hex` colour, with `imageFit`, `imageAspectRatio` and `cardSize`), and the view's properties with their names. A `list` view is a line for each note with its properties after the name (`markers`, `indentProperties` and `separator`). A view type that the app does not know is shown as a table. A filter that the app cannot read is shown above the view and is not applied.
- **Pictures:** a picture file (PNG, JPEG, GIF, WebP, SVG, BMP, AVIF, HEIC, HEIF or TIFF) opens in the app on its own page, from the sidebar, quick open or a link such as `[[map.png]]`. The page fits the picture in the window and shows its size in pixels, its size on disk and its type. Pinch or ⌘-scroll to zoom around the pointer, and scroll or drag to move a large picture. Press + and − to zoom, 0 to fit and 1 for the actual size, or use the bar, View › Zoom In (⌘+), Zoom Out (⌘−), Actual Size (⌘0) and Zoom to Fit (⌘9). A double click goes between fit and 100 %. The zoom goes to 1600 % and an SVG stays sharp. "Open in Default App" opens the file in the app the system gives it to. A transparent picture shows a checkerboard behind it. A picture has no editor, and the inspector shows the notes that embed it or link to it.
- **Pictures in a note:** a click on an image or a Mermaid diagram shows it as large as the window, with the same zoom, keys and bar. Escape or a click outside the picture closes it. An animated GIF, WebP or PNG moves in the reader and in the editor (not with Reduce Motion in the editor).
- **Canvas:** a `.canvas` file (Obsidian Canvas, JSON Canvas 1.0) opens as a board that you can read but not change. Scroll or drag the background to move the board. Pinch, ⌘-scroll or press + and − to zoom, and press 0 to see all of it. A text card shows its Markdown as the reader does. A file card shows the note (or its `subpath` section), the picture or the base, and a click on it opens the file. A link card shows its web address. Groups are frames with their labels. Edges are curves with arrows and labels. The six preset colours are red, orange, yellow, green, cyan and purple of naz and Daylight, and a `#hex` colour is used as it is. Canvases are in the sidebar and in quick open.
- **Quick open:** ⌘P or ⌘O finds a note, a base, a canvas or a picture by its name. Obsidian's excluded files (`userIgnoreFilters`) stay out of it and out of search.
- **Hidden files:** files that are not for people are not in the file tree, quick open, search, the graph, the backlinks or the recent notes. These are Obsidian's excluded files (`userIgnoreFilters`, for example an `uploads/` folder and all that is in it) and files for AI agents, by name in any folder: `CLAUDE.md`, `AGENTS.md`, `GEMINI.md` and `CLAUDE.local.md` at first (`files.hidden` in the settings file). A link or an embed to a hidden file still opens it or shows it. View › Show Hidden Files (⇧⌘.) shows them all.
- **Files:** ⌘N makes a note in the open note's folder, ⇧⌘N a folder. Rename (⌘R), move (⌥⌘M, or drag onto a folder in the sidebar) and move to the Trash, from the File menu or a right click. When a file or a folder moves, every link to it in the vault follows, in the style it was written, as Obsidian's "always update links" does. A folder note takes its folder's new name.
- **Inspector:** the outline in the heading colors, with the section on screen marked, the backlinks, the outgoing links (a missing note in red) and the tags of the note. In the editor, the outline marks the section of the cursor, and a click on a heading puts the cursor on it.
- **Edit a task:** a right click on a task, in a note or on the Today page, opens a form for its text, status, reason, priority, due, scheduled and start dates and repeat rule. It writes the line in the Tasks plugin's order and keeps the tags, the block ID and the rest.
- **Statuses and reasons:** the statuses are the Tasks plugin's settings in the vault, custom ones too (such as `[r]` In Review), shown by name, on the board in the column of their type. A task can say why it is cancelled or waiting with a `[reason:: …]` field, which every list shows after the text with a 💬; cancelling a task from a menu or the board asks for the reason, and any other change of status takes the old one away. Queries read `has reason`, `reason includes …`, `status.name is …`, and `task.reason` in a function.
- **Tags:** the sidebar lists the vault's tags as a tree, `#a/b` under `#a`, each in its color with its count. A click lists the notes.
- **Missing links:** a click on a link to a note that is not there yet makes the note and opens it in the editor.
- **Paste as Markdown:** rich text pasted from a web page, Google Docs or Word keeps its headings, emphasis, links, lists, quotes, code and tables as Markdown; ⌥⇧⌘V pastes the plain text. A code editor's coloured lines stay plain.
- **Line and heading keys:** ⌥⌘1 to ⌥⌘6 make the line a heading (the same level again, or ⌥⌘0, takes it off), ⇧⌥↑ and ⇧⌥↓ copy the lines, ⇧⌘K deletes them, ⇧⌘X strikes the selection through and ⇧⌘C makes it code.
- **Block links:** ⌥⌘B (Copy Block Link) gives the paragraph or list item at the cursor a `^id`, as Obsidian does, and copies its `[[Note#^id]]` link. A table, a quote or a code block gets its id on a line after it. When you pick a block without an id in `[[Note#^`, the app adds the id to that note. The reader goes to the block that a link names and marks it for a moment, and `![[Note#^id]]` shows only that block.
- **Slash commands:** in the editor, `/` at the start of a line or after a space shows a small list under it: headings, tasks, lists, a callout of each kind, code, Mermaid, math, a table, a rule, links, the date and the time, and the six highlight colors. Type to filter the list (`/tab`, `/h2`, `/warn`). ↓ and ↑ (or ⌃N and ⌃P) choose a row, Return or Tab inserts it in place of the `/` and what you typed, as one step to undo, and Escape closes the list and leaves the text. The list never takes the keyboard, so you can type on. It does not open in code, the front matter, math or a comment, with many cursors, in Neovim mode or in a read-only vault. `editor.slash_menu = false` turns it off.
- **Extract:** ⌥⌘X moves the editor's selection to a new note and puts a link to it in its place, as Obsidian's note composer does.
- **Many cursors:** in the editor, ⌥⌘E (Edit › Select Next Occurrence, as in Xcode) selects the word at the cursor, and then each next place of the same text as one more cursor. ⌃⌘G (Select All Occurrences) selects all of them at once. ⌥-drag selects a column, and a drag straight down puts a cursor on each line; ⌃⇧-click adds a cursor. Typing, Backspace, Delete, Return, Tab, the arrow keys and paste act at every cursor, and a paste with one line for each cursor gives each cursor its line. Each key is one step to undo. Escape goes back to one cursor.
- **Typewriter and focus:** View › Typewriter Mode keeps the cursor's line in the middle of the editor while you type, also the last line. View › Focus Mode dims all paragraphs but the paragraph that has the cursor to 45%, with their callouts, tables, task boxes and pictures; a selection keeps each paragraph that it touches bright, and many cursors keep each cursor's paragraph. The change from one paragraph to the next is a short fade. Both are settings (`editor.typewriter` and `editor.focus`) and are off at first. With Reduce Motion, the editor jumps and does not glide or fade.
- **Spelling:** the editor marks words that are spelled wrong as you type. Each line is checked in its own language, as its direction is found: from its first strong letter. macOS has no Persian dictionary, so Persian lines are not marked (the Arabic dictionary would mark many Persian words). Code, code blocks, web addresses, the target of a wikilink, embeds, tags, math and the front matter are not marked. View › Check Spelling While Typing (`editor.spell_check`) turns it off.
- **Folded notes:** in the reader a section folds shut from its heading (the chevron, or `z`; `Z` folds or opens them all), and a folded heading says what is under it: how its text begins, how many words, how many sections. A vault can say that its notes open folded, with `folded = true` under `[reader]` in the `.daftar.toml` at its root; Settings › Appearance › Notes open folded follows the vault, or always or never folds. A note opened folded reads as its own table of contents: its top headings, each with its hint. A note whose sections you fold or open yourself opens as you left it, and a link, the reading place and find open the folds that hide what they show. The note's file is never changed by a fold.
- **Tabs:** a window has tabs of its own, in a bar over the note when there is more than one. ⌘T opens a tab, ⌘-click on a link opens the note in a new tab, ⌃Tab and ⌃⇧Tab (or ⇧⌘] and ⇧⌘[) show the next and the previous tab, and ⌘W, the cross on a tab or the middle button closes a tab; the window's red button closes the window with all its tabs. A tab is dragged to another place in the bar or to the bar of another window, and Window › Move Tab to New Window and Merge All Windows do as they say. The tabs share the window's sidebar, toolbar and inspector, so a new tab and a switch of tabs are immediate. A tab left stays as it was: its page where you read, its editor with its cursor.
- **Split view:** ⌘\ (View › Split Right) shows a second note pane beside the note. Each pane has its own note, reader or editor, history and find. Click a pane to give it the focus; a thin accent line shows the focused pane, and Quick Open, ⌘E, the history and the inspector act on it. ⌥-click on a link opens the note in the other pane. ⌘\ again, or the × on a pane, closes the split. When the same note is in the editor in both panes, each pane saves when you leave it and shows the saved text when you come back. In Neovim mode, only one pane can edit at a time.
- **Command palette:** ⇧⌘P runs any command by its name, with a fuzzy match, and keeps the commands you used last at the top.
- **Link preview:** hold the pointer on a link to a note to see the note, or the section or the block the link names, in a card. The editor shows the same card for a `[[link]]`, drawn or raw: the note's title, the heading and the folder at the top, and the first lines of the note below. A click on the top of the card opens the note. The card goes when the pointer leaves it, and at once when you type, scroll or click. `appearance.link_preview = false` turns it off.
- **Section bar:** once the heading of the place you read has left the view, a thin bar at the top of the reader shows its path (`Plan › Next › Budget`). A click on a heading goes to it. `appearance.section_bar = false` turns it off.
- **Tables in the reader:** a long table keeps its header row at the top of the view while you read its rows. A click on a header cell sorts the rows by that column: small to large, then large to small, then the file's order again. Numbers sort as numbers, empty cells go last, and the file is never changed.
- **Footnotes:** a click on a footnote's number, or resting the pointer on it, shows the footnote in a card where the number is, with no jump to the end of the note. Escape, a click outside or a second click closes it.
- **Soft changes:** another note, and the change between reading and editing, fade in over 120 ms with no movement. Reduce Motion makes every change at once.
- **Bookmarks:** ⌘D bookmarks the note. The sidebar shows the bookmarks at the top, from Obsidian's own `.obsidian/bookmarks.json`, groups too, and keeps the kinds it does not show when it writes the file. A bookmark follows its file when the file moves.
- **Graph:** ⌥⌘G shows the open note and the notes up to four links away, or the whole vault. Each top folder has its color, a note grows with its links, and a click opens it.
- **Periodic notes:** ⌘3 opens the note of this day, week or month, as the Daily notes plugin names it (`.obsidian/daily-notes.json`), and makes it from the plugin's template when it is not there yet. On a periodic note, the bar above it has arrows to the nearest earlier and later notes (⌥⌘← and ⌥⌘→), and a menu with the same time in earlier years.
- **Templates:** New Note can start from a note in the Templates plugin's folder (`.obsidian/templates.json`, or `Templates/`), with `{{title}}`, `{{date}}`, `{{time}}` and `{{date:FORMAT}}` filled in.
- **Reading keys and time:** in the reader, `[` and `]` go to the previous and the next heading. The bar above a note says how many words it has and how long it takes to read.
- **Folding:** a chevron before a heading folds its section shut, as in Obsidian's reading view; `z` folds the section of the reading cursor and `Z` folds or opens them all. Each note remembers its folds.
- **Updated since you read:** the notes that changed on disk since you last read them, by a pull or another app, are listed at the top of the sidebar and marked with a dot in the tree. The app's own edits do not count.
- **Read aloud:** ⌥⌘R reads the note from the reading cursor on, a paragraph at a time, each in its own language when the Mac has a voice for it (a Persian voice for Persian). The page marks the paragraph being read; Escape or ⌥⌘R again stops.
- **Export as PDF:** ⇧⌘E makes an A4 PDF of the note with `daftar-cli export` (`brew install parham-alvani/tap/daftar-cli`), from the reader or the editor, for someone who does not read markdown: Typst sets it, with `export.logo` and the logo of the note's folder at its head and `export.footer` at its foot, the same file Daftar for Linux and a script make.
- **Problems:** ⇧⌘M (View › Show Problems, or the command palette) opens a panel under the note with what `just audit` and `just check` report: the audit, lint and formatting of `daftar-cli check`, `lint` and `fmt --check`, by note, errors first, with a filter for errors, warnings or both. A click opens the note at the line: the reader puts its reading cursor there, the editor its cursor. Fix mends a finding that has one answer, and Fix All does what `just fix` does, in a note or in the whole vault; an open editor saves first, and takes the mended note after. The vault is checked in the background when it opens and a moment after each save, and the toolbar shows the count of errors (or warnings). In the editor, a line with a problem has a red or yellow dot in its margin, with the message on hover. Escape closes the panel. Needs `daftar-cli` 0.23.0 or later.
- **Format on save:** when you leave a note you typed in (⌘E back to the reader, another note, closing it, quitting), the editor formats it with `daftar-cli fmt`, as `just format` does, with the vault's `.prettierrc`. It never formats while you type, so the text never moves under the cursor, and a note already formatted is not touched. Edit › Format Note (⌥⇧⌘F) formats at any time, as one step to undo, in Neovim mode too. `editor.format_on_save` turns it off.
- **Addresses and phone numbers** written as plain text are links: an address opens Maps, a number the app that makes calls. The inspector lists the places a note names.
- **WakaTime:** a setting sends the time spent reading and writing each note to WakaTime with `wakatime-cli`, as Obsidian's WakaTime plugin does. It is off at first.
- **History:** ⌥⌘Y shows each commit that changed the note, newest first, across renames, with the lines it added and removed or the whole note as it was then. Restore This Version gives the note an older text again; the next sync commits it, so the newer text stays in the history.
- **Sort tasks:** File › Sort Tasks puts the done and cancelled tasks first and the open ones last in each section, with the lines under each task, as the vault's Task Sorter plugin does. In the editor it is one step to undo.
- **Postpone:** a right click on a task on the Today page or the board postpones it by a day, some days, a week or a month, as the Tasks plugin's menu does: its due date moves, or else its scheduled or start date, and a date already past moves on from today.
- **Rename a heading:** when you change the text of a heading in the editor and move the cursor off its line, a bar under the note asks to update the links to the old heading: `[[Note#Heading]]`, with an alias, an embed, a nested `[[Note#Parent#Heading]]`, `[[#Heading]]` in the note itself and `[x](Note.md#Heading)`. The bar shows each line before and after. Update writes them; Not Now leaves them. File › Rename Heading… does the same for the heading of the cursor's section. A link finds its heading as Obsidian does, without case and marks, so a link to a different heading with a similar name does not change.
- **Move a section:** ⌥⌘↑ and ⌥⌘↓ move the section of the cursor, with its heading, its text and its subsections, above the previous or below the next section of the same level. Above the first heading, they move the lines, as ⌥↑ and ⌥↓ do. In the editor it is one step to undo. You can also drag a heading in the inspector's outline onto another heading of the same level.
- **Rename a tag:** a right click on a tag in the sidebar renames it in every note, in the text and in the `tags` property, and the tags under it too: `#work/alpha` follows `#work`. Code and links keep their text.
- **Scratchpad:** ⌥⌘S (File › Scratchpad, or the command palette) opens the scratchpad, the vault's one inbox note `Scratchpad.md`, in the editor with the cursor at its end, and makes it empty when it is not there yet. It never makes a note for each day. `scratchpad.note` in the settings file (Settings › Capture) names another note; quick capture adds to the same note with `capture.target = "Scratchpad.md"`.
- **Quick capture:** a global shortcut (⌃⌥N at first, a setting) opens a small panel over any app, also with no Daftar window open. Return adds the line to today's note, ⌘↩ adds it as a task. The note and a heading to add it under are settings, and the heading may hold the day (`## {{date:YYYY-MM-DD}}`), so one inbox note gets a section for each day; the menu bar, the File menu and the command palette open the same panel.
- **Send to Daftar:** in any app, select text and choose Services › **Add to Daftar Scratchpad** (in the app menu or the right-click menu) to add it to the scratchpad under today's `## YYYY-MM-DD` section, as a list item; a web address is written as `<https://…>`, and a link selected in a browser as a Markdown link. **New Daftar Task** opens the New Task form with the selection as its text. Both work with no Daftar window open, and System Settings › Keyboard › Keyboard Shortcuts › Services can give them shortcuts.
- **Replace in the vault:** ⇧⌘H (Edit › Replace in Vault…), or Replace in Folder… on a folder in the sidebar, finds a text or a regular expression in every note and shows each match on its line, before and after. Match Case, Whole Word and Skip Code (on at first) narrow the matches; in a regular expression, `$1` in the replacement is the first group. Only the checked matches are replaced. A note that changed after the preview is not written. The next sync commits the change, so the history keeps the old text. Excluded files are left out.
- **Hide the menu bar:** a setting hides the menu bar while Daftar is in front.
- **Home:** a window or a pane with no note open shows the time, the date, a greeting, a field that finds a note (Return opens the best match), the notes you read last and a quote, in glass cards over your own picture. The page uses the settings of Obsidian's Beautitab plugin in the vault. The picture is the `home.image` setting (Settings › Home): a PNG, JPEG, HEIC or WebP file, with an absolute path, a `~` path or a path in the vault. With no picture the page is plain. In a split window, each empty pane shows a smaller page.
- **Today:** the meetings of the day from the week notes in `Calendar/` (which Daftar on the phone writes), the free time, and the tasks that are overdue, due, in progress and coming. A click on a checkbox completes a task, also a repeating one, as the Tasks plugin does. A task can also repeat by the Jalali calendar, on the same day of the Solar Hijri month: `🔁 every jalali month` (or `every 3 jalali months`, `every jalali year`, with `when done` too) moves a ⏳ on Dey 10 to Bahman 10, where `every month` would drift off it ([spec](https://github.com/parham-alvani/notes-linux/blob/main/docs/specs/jalali-recurrence.md)).
- **Review Cards:** ⇧⌘R (Go › Review Cards, or the command palette) drills the notes of questions in `Learning/Interview-Preparation` by spaced repetition, as `daftar-cli drill` does: each heading is a card, the headings above it are its context, and its section is the answer. Space or Return shows the answer as the reader draws it (Persian right to left), and 1 to 4 or the buttons rate it Again, Hard, Good or Easy, each button saying when the card comes back (SuperMemo's SM-2). The cards due come first, then ten never asked; a forgotten card is asked again at the end. `e` opens the card's note at its heading, and Escape leaves. A bar shows how far the session is, and the last page says when the next cards are due. No note is written: the reviews are in `~/.local/state/daftar/drill-<hash>.json` (`$XDG_STATE_HOME` is honoured), the same file `daftar-cli drill` and its MCP tools read and write, so a card rated in one is rated in all. Today and the sidebar show how many cards are due.
- **Job search:** ⇧⌘J (Go › Job Search, or the command palette) shows every note with a `job_stage` property as a card on a board, a column for each stage that is going (applied, screening, interviewing, offer, accepted) and the closed ones (rejected, withdrawn, declined) folded into one column that opens with a click. A card has the company's logo, its role, the channel it came by, the next booked event (`job_next`, on Madrid's clock) with a link to its `Interview Preparation.md`, and a "Quiet" mark when nothing in the note is dated in the last 30 days, as `daftar-cli check`'s `memory-quiet` warns (the vault's `.daftar.toml` can change the stages and the days). The events of the next 14 days are above the columns, and Channels shows how each channel did. Drag a card to another column to change its `job_stage`; only that line of the note is written. Today shows the next booked event.
- **Weekly review:** ⌘4 (Go › Weekly Review, or the command palette) opens this week's review, the note `daftar-cli review` writes in `Reviews/` every Saturday (`Reviews/2026-10-31 to 2026-11-06.md`). When it is not there yet, the reader shows a preview of it, made by `daftar-cli review`, with a Save to Reviews/ button that writes it (`--write`, never over a note); Escape closes the preview. The Today page links the newest review.
- **Notifications:** an alert before each meeting, with a Join button, and a morning digest of the tasks that are due. Rules of your own, `[notifications.rules.<id>]` in the settings file or the vault's `.daftar.toml`, ring at a time of the day when a note has no heading for today (`Diet/Diary.md` with no `### 25 Nov 2026 · Wednesday` at 21:00), and a click opens the note ([spec](https://github.com/parham-alvani/notes-linux/blob/main/docs/specs/notification-rules.md)).
- **Menu bar and Dock:** today's meetings and tasks in the menu bar, and the count of tasks due on the Dock icon.
- **Git:** commit, pull with a rebase, and push, with the system `git` and your own SSH keys. The toolbar shows the branch and the changed files. The app pulls when it starts, and automatic sync is a setting that is off at first.
- **Several vaults:** Daftar keeps a list of the vaults this Mac knows (`vaults` in the settings file, beside `vault`, the one in use). File › Switch Vault, the command palette and Settings › Vault change to another one in the running app, with no restart: the notes you are editing are saved first (a save that fails stops the change), a sync that runs finishes first, and the index, the search, the settings the vault carries, its task statuses and its read-only mark are all read again, so nothing of the vault before is left. Each vault keeps its tabs and reading places and shows them again when you come back, in the window you are in; any other window shows the home page. Open Vault… (⇧⌘O) adds a folder to the list. A folder that is gone stays in the list as missing, and Forget Vault takes one out without touching a file. One vault is open at a time; for two side by side, start a second Daftar with `open -n`.
- **A read-only vault:** a clone on a computer that must not change the vault (a work laptop, a server, a key without write access) is made read-only in Settings › Vault, or with `git config --local daftar.readonly true` in the vault. Daftar then writes no file of the vault and makes no commit: the editor, new notes and tasks, capture, moves, renames, deletes, Format Note and Fix are off, a task's box does not tick, and the sync is a pull that only fast-forwards. The toolbar shows "Read-only". Reading, search, tasks, Today, the board, the history and export work as before. A clone that has changes of its own is not mended: the pull fails and names the files. When the remote refuses a push because the key cannot write, the notice offers Make This Vault Read-only.
- **The clone's own git settings:** Settings › Vault › Git holds what belongs to this clone alone, in its git config, never committed: Read-only, the address it pulls from and pushes to (to move to a mirror when the first host cannot be reached), the name and email of its commits, and its SSH key (choose a file, or Generate a new one in `~/.ssh` and copy its public key). Daftar keeps the clone's `core.sshCommand` when it runs git.
- **Sync conflicts:** when a pull stops on a conflict, Daftar keeps the rebase open and shows the conflicted files, with a badge in the toolbar. For a note, each conflict shows the lines on the remote beside your change; Keep Remote, Keep Mine or Keep Both (yours after the remote's) for each conflict or for the whole note, or Edit opens the note with the conflict marks. Other files keep one side whole, and a deletion is a side. Finish Sync commits the result, goes on with the rebase and pushes; Abort Sync puts your commits back as they were before the pull. Automatic sync waits while a conflict is open, and a rebase left open is shown when the app starts.
- **Concepts (Open Knowledge Format):** a note whose properties have a `type` is a concept, as the [Open Knowledge Format](https://github.com/open-knowledge-format/open-knowledge-format) 0.3 has it. The inspector shows its type and, in chips, whether it is unverified, machine-confirmed or human-reviewed (from `verified` and `generated`), a status that is not stable, and "Stale since" when its `stale_after` has passed. The reader has one line above a deprecated or a stale concept, with a link to the concept that replaces it (`superseded_by`), and quick open and search show a deprecated concept dimmed, after the others. Mark as Verified (the inspector, or the command palette) adds your name and the time to `verified` and changes no other line. A Markdown link, `[text](target)`, resolves as OKF says: from the note's folder, or for a `/` path from the bundle's root (the nearest folder whose `index.md` has `okf_version`, else the vault), and it counts as a link in the backlinks, the graph and a move.
- **Terminal:** ⌃` opens your login shell in the vault's folder, under the note, in the same colors.
- **Icons:** the folders and notes show the icons and colors of the Iconic plugin. A `logo.svg` (or `logo.png`, `.webp`, `.jpg`) in a folder is that folder's icon, for example a company's logo on its folder; the file itself is not listed. Daftar on Android shows the same logos.
- **Breadcrumb:** a bar above the note shows the vault, its folders and the note. A folder opens a menu of what is in it, and the note's crumb has the file commands.
- **Quick Look:** the space bar on a `.md` file in Finder shows the note as the reader draws it: callouts, highlights, tags in their colors, Persian right to left, and the Daylight or naz colors of the system appearance. Wikilinks show as links but do not open, and images that the note embeds from its vault show too. The preview comes with the app; open Daftar once after an install so that macOS finds it.
- **Accessibility:** VoiceOver says the name of each icon button, and says in words what a color or an icon shows: a task's status, its priority, an overdue date, a note changed since you read it, the focused pane. Task rows and board cards are one element each, with actions to complete, edit or move the task. In the reader, the checkboxes, fold chevrons, copy buttons and canvas cards have names, a canvas has a list of its cards and arrows, and pictures open with Return. Tab reaches the board cards, the canvas cards and the reader's controls. Escape closes every sheet and panel, and Return does the main action of a sheet that has one. The app and the reader follow Reduce Motion and Increase Contrast.
- **Large vaults:** a vault of 20,000 notes opens in about two seconds on an M4 Pro, a search, a task query or a key in quick open takes less than a tenth of a second, and a saved note is in the index in about as long. `just bench` makes such a vault and shows the times.

## Configuration

Every setting is in one file, `~/.config/daftar/config.toml`. The app makes it on the first start, with a comment on each setting. Edit it in any editor and the app follows the change at once, or use the Settings window, which writes back only the value that you change. The file is safe to keep in your dotfiles.

The settings are kept in the vault, so a change on one device reaches the others. The `.daftar.toml` at the vault's root may hold the same sections and keys as `config.toml`, and its value wins over the computer's. **A setting changed in the app, in Settings, by the zoom or in the export panel, is written to the vault's `.daftar.toml`**, on the line of that key alone, and the next sync commits it. In Settings such a setting shows "From the vault". Right-click a setting for Keep on This Device, which keeps this Mac's own value in `config.toml` (the key joins `vault_settings`), and Follow the Vault, which gives it back.

The file may hold a table for each platform, `[macos]`, `[linux]` and `[android]`, with the same sections under it, and each app reads its own table over the shared sections. The Mac writes to `[macos]` the settings that differ by platform (`appearance.font`, `appearance.code_font`, `terminal.font_size`, `capture.hotkey`), a key that table has already, and the settings only the Mac has:

| Section | Keys only the Mac has, kept in `[macos]` |
| --- | --- |
| `[macos.appearance]` | `dock_badge`, `spotlight`, `hide_menu_bar` |
| `[macos.editor]` | `properties_form`, `typewriter`, `spell_check`, `animate_cursor`, `cursor_trail`, `cursor_effect`, `option_as_meta`, `blur_panels` |
| `[macos.meaning]` | `search`, `refresh_minutes` |
| `[macos.home]` | `new_tab` |

A change stays in this Mac's `config.toml` when a repository may never hold it: a key that names a program (`terminal.shell`, `editor.vim_mode`, `editor.nvim`, `editor.nvim_config`), sends something out (`wakatime`), says who you are (`okf.actor`) or which vaults this Mac has (`vault`, `vaults`, `vault_settings`); a value a vault may not hold (pictures from the web turned on, a picture outside the vault); a key this Mac keeps; and every change in a read-only clone, or in a folder that is no repository and has no `.daftar.toml`. `git.name` and `git.email` in the vault's file are the author of commits in a clone that names none. `vault_settings = false` at the top of `config.toml` reads no setting from any vault and writes none to it, and a list, as `vault_settings = ["appearance.theme"]`, keeps only those keys on this Mac. A vault can also keep agents out of every read-only clone, with `read_only_clones = false` under `[agents]`: Apple Intelligence then reads no note there.

## Build

The build needs Swift 6 (the Xcode command line tools are sufficient), Node.js and [just](https://github.com/casey/just).

```bash
just test     # the Swift tests and the renderer tests
just app      # build/Daftar.app
just run      # build and start it
just install  # copy it to /Applications
```

Xcode is not necessary. The code uses no SwiftUI macro, because the plugin for those macros ships only with Xcode.
