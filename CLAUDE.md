# CLAUDE.md

Guidance for Claude Code in this repository.

## What this is

**Daftar for macOS**: a native SwiftUI app for an Obsidian vault in a Git repository, meant to replace Obsidian on the Mac. It is the sister of `../notes-droid` (Daftar for Android). The two apps share no code, but they share rules: how a wikilink resolves, what a task line is and how it is ticked, the format of the week notes in `Calendar/`, and the colors. When a rule changes in one, change it in the other.

The repository is **public**; the vault it reads is private. Every test fixture is synthetic.

## Commands: always `just`

```bash
just test   # swift test + node --test for the renderer
just app    # build/Daftar.app, ad-hoc signed
just run    # build and open it
just web    # rebuild the reader bundle only
just icon   # Support/Daftar.icns from art/icon.png
just bench  # the timings of a made-up 20,000-note vault, release build
```

## Layout

```text
Sources/DaftarCore/   no AppKit: parser, link resolver, tasks, calendar, search, git
Sources/DaftarUI/     the SwiftUI app, as a library the tests can drive
Sources/Daftar/       main.swift only
Sources/DaftarQuickLook/ the Quick Look extension (`just app` makes Contents/PlugIns/DaftarQuickLook.appex from it and Support/QuickLook)
Sources/DaftarUI/Reader generated by `just web` from web/src -- never edit, not committed
web/src/              the reading view: markdown-it with Obsidian's syntax
web/dist/quicklook.js generated by `just web` from web/src/quicklook.js, for the Quick Look extension -- not committed
Tests/                swift-testing, synthetic vaults in temporary folders
```

Keep logic in `DaftarCore`: its tests run in a second and need no window. `Tests/DaftarTests` drives the app's own views in-process (the editor's keys, saves and images) on a vault in a temporary folder, with its own `AppSettings(url:)` and `VaultStore(settings:openVault: false)`: a test must never reach the person's config file or vault.

## Toolchain traps

- **No Xcode on this machine, only the command line tools.** In the macOS 27 SDK, `@State` and `@Entry` are macros, and the `SwiftUIMacros` plugin ships only with Xcode. Write `@ViewState` (a type alias of the `State` property wrapper, which no macro shadows) and a plain `FocusedValueKey` or `EnvironmentKey` instead of `@Entry`. Do not build against an older SDK to avoid this: SwiftTerm 1.99 needs the Swift 6.4 standard library of the 27 SDK.
- **The app targets macOS 26** (Liquid Glass, Foundation Models, Writing Tools), so the newest APIs need no `#available`. Without Xcode there is no App Intents metadata processor (Shortcuts and Spotlight actions do not register), no `@Generable` (`FoundationModelsMacros` ships with Xcode), and no Icon Composer: use plain-string Foundation Models calls.
- **Glass does not show in `cacheDisplay`.** The window server draws Liquid Glass, so an off-screen snapshot shows white where glass is. To see it, run the second copy of the app and capture only its window: `screencapture -x -o -l <window number>`.
- **The Quick Look extension is built without Xcode.** It is a SwiftPM executable whose `main.swift` calls Foundation's `NSExtensionMain` (found with `dlsym`), so it needs no `-e _NSExtensionMain` linker flag; `just app` puts it in `Contents/PlugIns/DaftarQuickLook.appex` with `Support/QuickLook/Info.plist`, `quicklook.js` and the reader's CSS. Sign inside out and never with `--deep`: `--deep` signs the extension again without its sandbox entitlement, and Quick Look refuses an extension without the sandbox. Ad-hoc signing is enough on macOS 27.
- **Quick Look shows HTML without running its scripts.** The extension renders the note with the reader's own `render.js` in JavaScriptCore (`QuickLookPreview.Renderer`) and gives Quick Look the finished page; what `reader.js` does to the page afterwards (tag colours, code headers) `quicklook.js` does on the string. Pictures go as `cid:` attachments.
- **macOS takes a Quick Look extension only from an app that was opened once.** `pluginkit -a` or `lsregister` on a build that was never launched gives "plug-ins outside containing apps must be protected by SIP" in `pkd`'s log. To test, copy `build/Daftar.app` with another bundle ID (`me.parham1995.qltest`, extension `me.parham1995.qltest.quicklook`, no URL scheme), sign it again, `open -n` it once, quit it, then `qlmanage -p note.md`; afterwards `pluginkit -r` and `lsregister -u` the copy and delete it, so it never takes `daftar://` or the preview from the installed app. A vault in `/private/tmp` shows no pictures (the sandbox exception covers the home folder only), and one in `~/Documents` makes macOS ask for access to Documents: test in a synthetic folder in the home folder.
- **Core Spotlight refuses an ad-hoc signed app** (`CSIndexErrorDomain -1000`, XPC 4099). `Spotlight` is ready for a signed build and fails silently until then.
- **`Regex` is not `Sendable`.** A shared pattern is `nonisolated(unsafe) static let`; its lazy compile is thread safe, and the index parses notes on many threads.
- **No lookbehind** in Swift regex literals.
- **A test target that depends on an executable target, or on anything with SwiftTerm's build-tool plugin in its graph, loses the swift-testing macro plugin** under the command line tools (`plugin for module 'TestingMacros' not found`). That is why the app is the `DaftarUI` library with a one-line `main.swift`, and why `Package.swift` names `libTestingMacros.dylib` for test targets when Xcode is not installed.
- **A `.task` on a `Group` with nothing in it never runs**: the modifier goes to each child, and there is none. Put a view that waits for its data in a `VStack` (`HeadingLinksBanner`).
- **`Settings` is a SwiftUI scene.** The app's own settings class is `AppSettings`.
- **`UNUserNotificationCenter.current()` aborts outside an app bundle** (`swift run`). `Notifier` checks for a bundle identifier first.
- **A `daftar://` URL opens a new window unless the window says otherwise.** `handlesExternalEvents` on the scene and on `ContentView` keep it in the open window.

## Rules the code keeps

- **Every setting is in one file, `~/.config/daftar/config.toml`** (`$XDG_CONFIG_HOME` is honoured). Nothing goes into `UserDefaults`. `ConfigFile` reads a small TOML subset and writes a changed value on its own line, keeping the person's comments. A new setting gets a line in `ConfigFile.template`, a property in `AppSettings`, and a control in the Settings window; the app follows edits to the file while it runs. Window frames that AppKit saves by itself are not settings.
- **What the app keeps for itself is state, not a setting**, and goes in `AppSettings.stateDirectory`: `~/Library/Application Support/Daftar`, or a `state` folder beside the config file in a test or with `$XDG_CONFIG_HOME` set, so a test never writes to the person's Library. What it keeps of each note (`ReadingPlaces`, `PlaceBook`) is such state: the reading place, the folded sections and when the note was last read, in one file for each vault, written a second after a change and on quit. An edit of the app's own marks the note read, so only a pull or another app makes a note "updated since you read".

- **An edit reads the file again and refuses when the line changed.** `VaultEdits.toggleTask` checks that the clicked line is still a task with the status the view showed. Never write from what the view or the index remembers.
- **The index is in memory and is built at launch.** The files are the record; there is no database on disk to migrate. File events are gathered for 250 ms and applied together.
- **The reader page reaches nothing but two schemes:** `daftar://reader/…` (the bundle) and `vault:///…` (the vault, and nothing outside it). The page has a content security policy; keep `script-src 'self'`.
- **The week notes in `Calendar/` are read-only here.** The phone writes them whole at every change; see `Calendar/CLAUDE.md` in the vault for the format.
- **Git runs with `GIT_TERMINAL_PROMPT=0` and `ssh -o BatchMode=yes`.** A sync that needs a password fails and says so; it never waits. Commit messages use the obsidian-git format of the vault's history: `update notes @ 2026-10-25 09:30:00 on host`.
- **Colors are Daftar's:** naz on dark, Daylight on light, copied from `notes-droid/app/.../ui/theme/Naz.kt` and `Markup.kt`. They are in `web/src/reader.css`, in `Palette` (`WindowModel.swift`) and in the terminal's ANSI palette (`TerminalPane.swift`). Iconic's colour names map to naz as `IconColors.kt` does on the phone.
- **Iconic's icons are Lucide names; the tree draws SF Symbols.** `IconicImage.symbols` maps the ones the vault uses. A new icon in the vault needs a line there; an unknown or missing symbol draws the default icon.
- **The editor is TextKit 2 and never changes text to draw something.** Styling comes from `MarkdownHighlighter` (core, tested); an embedded image gets paragraph spacing and is drawn by `ImageLayoutFragment`, so the text, the cursor and undo see only `![[name.png]]`. An editor save goes through `VaultStore.write`; a change on disk is taken only when nothing is unsaved.
- **The editor styles only what an edit can change.** A key restyles its own lines; the rest of the note is restyled, from the edited line on, only when the note's structure changed -- its fence, `$$`, `%%` and `---` lines, in order (`EditorController.structure`, which runs on every key, so it reads first letters, not every line). A note opens with its first screens styled and the rest a part at a time. Text goes in with `setAttributedString` and plain attributes, never `string =`, which gives it the old text's attributes. A full restyle of a 70,000-character note is about 200 ms; a key must stay under a few.
- **The properties form writes only the lines it changed.** `PropertySheet` (core) keeps each property's lines as written and prints an untouched one byte for byte; a changed one keeps its quotes and its list style. YAML it cannot print back the same (comments, anchors, nested maps, block scalars, a key twice) is never a form: the editor shows it raw. The editor hides the front matter the form shows with attributes (`collapseFrontMatter`) and keeps the cursor and typing out of it (`PropertiesView.swift`); a form edit is `VaultStore.editProperties`, which saves the editors, reads the file again and refuses when the front matter is not the one the form showed. `PropertySheet` has a `RobustnessTests` line.
- **Live preview hides marks with attributes, never by changing text.** Away from the lines the selection is on, `.markup` spans, a markdown link's brackets and address, and a highlight's colour emoji get a 0.01 pt clear font; a quote's `>` and a callout's `[!type]` stay. A selection change restyles the old and the new lines only (`revealSelection`). The cursor never sits in hidden text, so the arrows never stop on it.
- **Many cursors are the editor's own, not the text view's.** `NSTextView` drops a caret from a list of selected ranges and types only into the first range. `EditorExtras.cursors` keeps every cursor, `CaretOverlay` draws the carets the view cannot hold, and the keys reach them through one-line hooks in `doCommand`, `insertText`, `paste` and `mouseDown` (`EditorCursors.swift`); the edits are `MultiCursor` (core, tested). All the edits of one key go in with `shouldChangeText(inRanges:)` in one undo group. The cursors hold while the view's own selection is what they set; a click, a find or an undo ends them. A test has no event loop, so it sets `groupsByEvent = false` to see one undo step for each key.
- **Focus mode dims with a rendering attribute and spelling is the text view's own.** Neither changes the text storage. Spelling forces English for Latin letters (`willCheckTextIn`) and keeps only the marks in `Spelling.parts` (`didCheckTextIn`): not code, links' targets, web addresses, tags, math or the front matter, and not a Persian line while the Mac has no `fa` dictionary (the macOS 27 this was built on has none; the Arabic one marks Persian words wrong).
- **`BufferMirror` keeps each line's UTF-16 length.** A Neovim edit is applied from the changed lines and the one before them, and a position is a sum of lengths: joining or counting the whole buffer at every key made Neovim mode lag in long notes. `BufferMirrorFuzzTests` checks thousands of random edits against a plain copy of the text.
- **The view scrolls with Neovim's window.** A `WinScrolled` autocommand sends the top line; the view takes it and the cursor together, in one scroll that glides (none with Reduce Motion, none past two screens).
- **` ```tasks ` queries are the phone's engine, ported:** `TasksQuery` and `TaskExpression`. A line they cannot read is listed above the result, never dropped. The page asks the app through the `tasks` message handler, and a note with a query is drawn again when any note changes.
- **Apple Intelligence runs on this Mac only.** `NoteAssistant` uses `SystemLanguageModel.default`, never Private Cloud Compute: the vault holds other people's notes.
- **Escape never takes a Daftar window out of full screen.** `FullScreenEscape` replaces `NSWindow.cancelOperation(_:)` for windows with the `daftar.main` tabbing identifier in full screen; every other window keeps AppKit's way.
- **Fonts are settings** (`appearance.font`, `appearance.code_font`), applied by `Fonts` to the editor and the terminal and as CSS variables to the reader. Persian always cascades to Vazirmatn.
- **Neovim mode is the vscode-neovim model:** `nvim --embed` owns the buffer and the file; `NeovimSession` applies each `nvim_buf_lines_event` to the view as the smallest edit (`BufferMirror`) and moves the selection from the cursor autocommand. The view refuses every edit of its own (`shouldChangeText`); text keys go through `interpretKeyEvents` so input methods work, and Control, Command and special keys are sent as Vim notation (`VimKeys`). Neovim saves: `:update` a second after a change and when the note is left -- but never after a delete: `autoread` marks a buffer whose file went away as changed, and the `:update` writes the deleted note back (`stop(writing: false)`). The grid size goes through `VimGrid`: a view off screen has a text container as wide as a CGFloat goes, and `Int(_:)` of that stops the app. Neovim positions are UTF-8 bytes; the view's are UTF-16 -- convert through `BufferMirror`, never by hand.
- **Every parser takes made-up text in `RobustnessTests`**, from a fixed seed, so a failure comes back on the next run. A new parser, or a new edit of a whole note, gets a line there: no crash, and the invariant it promises (an edit keeps every line, a sort sorted twice changes nothing, a diff takes the old text to the new).
- **Sort Tasks is the vault's own `task-sorter` plugin, ported:** done and cancelled tasks first, the open ones last, in each section. Keep `TaskSorter` and the phone's port the same.
- **A sync never commits over an open rebase.** A pull that stops on a conflict throws `Git.Stopped` and leaves the rebase open (`rebase-merge` or `rebase-apply`); `VaultStore.rebasing` then stops every sync until the person finishes or aborts in `ConflictSheet`. Before this, the next sync committed the conflict marks on a detached HEAD and every later pull failed. In a rebase git's "ours" is the upstream and "theirs" is the person's commit: say "On the remote" and "Your change", never ours and theirs. `rebase --continue` runs with `GIT_EDITOR=true`, in a loop, since the next replayed commit can stop too. `ConflictText` parses and resolves the marks and has a `RobustnessTests` line.
- **A note's history is `git log --follow`** (`Git.history`), and a restore is an ordinary `VaultStore.write`: the next sync commits it, so nothing in the history is lost.
- **The Quick Look preview reads, it never writes**, and follows no link. Its sandbox lets it read the home folder (`temporary-exception.files.home-relative-path.read-only`) for the pictures a note embeds; it scans the vault (the folder above with `.obsidian`) only when the note has links, and only the note's own folder when it is in no vault.
- **A canvas is read-only and drawn by the reader.** `Canvas` (core) decodes JSON Canvas leniently: an unknown key or node type, a missing id or an edge to nowhere is dropped, never an error. `web/src/canvas.js` draws the board; a file card's note is filled as an `![[embed]]`, and a checkbox on the board is never ticked. Preset colours `1`-`6` map to the palette's red, orange, yellow, spring green, aqua and purple.
- **A picture is read, never edited.** `Vault.isImage` (core) is the list of types WebKit draws; such a file opens in the pane on the reader's picture page (`showImage` in `web/src/reader.js`), loaded from `vault:` with its date in the address so a changed file loads again. `NotePane.canEdit` is false for it, so the editor never opens a binary file; the commands that read a note's text check `WindowModel.showsText`, and the palette drops `PaletteCommands.textOnly`. Zoom and pan are `PanZoom` (`web/src/viewer.js`, its math tested in node), for the picture page and for a picture opened large from a note: the picture is laid out at its natural size times the zoom (width and height, not a transform's scale), so an SVG or a diagram is drawn again at each size and stays sharp. The editor draws an animated picture's frames with `ImageAnimation` and `ImageAnimator` (`EditorImages.swift`), which only redraw the lines on screen.
- **A web view in a window behind others does not paint.** To capture the app's page with `screencapture -l`, bring the test copy to the front first (`NSRunningApplication(processIdentifier:).activate()`); a hidden window shows an empty reader that is not a bug.
- **Replace in Vault writes only what the preview showed.** `VaultReplace.replace` runs the match again on the text read from disk and refuses the note when its matches are not the ones shown; the write is `VaultStore.write`. Find and replace share `VaultReplace.Pattern` (an `NSRegularExpression`, so lookbehind works there), and "Skip code" uses `TagRename.fence`.
- **Sections and heading links follow the outline.** `Sections` (core) finds headings as `NoteParser` does (no setext headings, none in front matter, fences or comments; `RobustnessTests` checks they agree), and a section runs to the next heading of its level or above. A section moved keeps the blank lines after each section in place. `HeadingRename` finds a link's heading as Obsidian does (`HeadingRename.key`: no marks, no case; each `#` part under the one before; the first match wins). The editor compares its headings when the cursor leaves a heading line or the editor, never at a key; the links are written with `HeadingRename.apply`, which refuses a line that is not the one the preview showed, through `VaultStore.write`.
- **The dark palette is screen-only** (`@media screen and (prefers-color-scheme: dark)` in `reader.css`), so a PDF export or a print is always in Daylight.
- **A `@MainActor` suite's `.enabled(if:)` deadlocks the whole test run before it starts.** Put the condition in a global constant.
- **A window has one or two note panes (`NotePane`).** Each pane has its own note, mode, history and find; `WindowModel` keeps the panes and the focused one, and its `request`, `editing`, `path` and history commands act on the focused pane, so menus, quick open and the inspector follow the focus. A click in a pane gives it the focus (`PaneClicks`, a local mouse monitor) before the click acts. The editor saves when it stops being first responder and takes the file when it becomes first responder again with nothing unsaved, so the same note in the editor of two panes does not lose text. In Neovim mode only one pane edits (`WindowModel.oneEditor`): two Neovims would each own the same file. The split is not kept across launches; no window state is.
- **Quick capture works with no window open.** The store belongs to the app; `QuickCaptureController` gets it from the menu bar icon's label, which is there from launch. The shortcut is a Carbon hot key (`RegisterEventHotKey`, no Accessibility permission) and the panel is a non-activating `NSPanel`, so the app in front stays in front. A capture saves the editors, reads the file again and writes with `VaultStore.write`; `QuickCapture.append` (core) keeps every line.
- **Every control has a name VoiceOver can say.** An icon-only button gets `.accessibilityLabel` (and `.help`); a decorative image is `.accessibilityHidden(true)`; a row drawn with `onTapGesture` gets `accessibilityRow` (`Accessibility.swift`); what a colour or an icon alone says (status, priority, overdue, a dot, the focused pane) is said in words, from `Spoken` (core) for tasks. In the reader every control is a real `<button>` or has a `role` and a name (`web/src/controls.js`, tested in `web/test/a11y.test.mjs`). Animations go through `withMotion` or `motionAnimation`, and faint text through `.faint()`, so Reduce Motion and Increase Contrast hold. `AccessibilityTests` reads the views' tree with `NSAccessibility`; SwiftUI builds that tree only after the app gets `AXEnhancedUserInterface`, which the test sets.
- **The home page decodes its picture once.** A pane with no note shows `HomeView`; `HomePictures` decodes `home.image` off the main thread with ImageIO (no larger than 5120 px, as EXIF turns it) and keeps it by path and modification date, so a redraw never decodes. The page reads Beautitab's `data.json` (`Beautitab`, core, lenient) again each time it appears, never goes to the network (a web address or an online quote source is off), and the picture is `.accessibilityHidden`. ImageIO reads WebP but cannot write it: a test's WebP is a byte literal.
- **Hidden files leave the lists, never the index.** `ExcludedFiles` is Obsidian's `userIgnoreFilters` and the `files.hidden` names (whole file names, in any folder); `VaultStore.excluded` is what the lists leave out now (nothing while `files.show_hidden` is on), `VaultStore.hidden` the rule itself, which Spotlight follows. A list a person browses (the tree through `store.tree` and `store.folder`, quick open, search, the graph, backlinks, recent notes, Today, the board) filters with `store.excluded`; the resolver, the reader and `daftar://open` never do, so a link or an embed to a hidden file still works.
- **A block id is read the same in the app and the reader.** `BlockRefs` (core) and `blockIds` in `web/src/render.js`: a trailing ` ^id` names its paragraph or list item (the `<li>`, since a tight list draws no `<p>`), and a `^id` line of its own, after an empty line, names the table, quote or code block above it. A new id is six lowercase letters and digits, free in the note, and goes in through the editor (a step to undo) or `VaultStore.addBlockId`, which reads the file again and refuses a block that changed. The editor's completion list shows labels (`alias → Note`, an indented heading, `#tag  3`); `CompletionState.choices` maps each label to the text it writes, so a label never goes into the note.
- **The terminal is SwiftTerm, pinned exactly.** It runs the login shell in the vault's folder and lives in the window's model, so hiding the pane keeps the shell.

## Performance

`just bench` (`BenchmarkTests`, on only with `DAFTAR_BENCH=1`) writes a vault from a fixed seed: 20,000 notes in nested folders, 53,000 tasks, front matter, links (broken, with an alias, with a heading), ` ```tasks ` queries, 70,000-character notes, Persian text, images and bases. It prints a table of the paths a person waits on. The budget on an M4 Pro, with the release build:

| Path | Budget |
|---|---|
| Open the vault (index and full-text search) | under 2.5 s |
| A saved note (watcher batch of 1) | under 150 ms |
| A pull of 500 changed files | under 300 ms |
| Full-text search | under 50 ms |
| Quick open, each key | under 100 ms |
| A ` ```tasks ` query over every task, or the Today page | under 100 ms |
| The whole-vault graph and its layout | under 1.5 s |
| Rename a note that 2,000 notes link to | under 1.5 s |
| Rename a tag in 6,000 notes | under 2 s |

A change that makes a row slower than its budget is a bug. To find a slow path, run it in a loop and `sample <pid>` the test process (Instruments needs Xcode). Rules the timings taught:

- **A regular expression runs only on a line that has its marks.** Swift's `Regex` is slow: test for the ASCII marks it needs first (`hasMark("[[")`, `mayHoldTag`), on the UTF-8 bytes, not with Foundation's `contains`. The test must be a condition the pattern cannot match without, so the result never changes.
- **No regex literal and no `Calendar(identifier:)` inside a function that runs per line or per task;** make it a `static let`.
- **A sort compares values worked out before it**, not in its comparator: titles, query groups, and positions rather than large structs.
- **`derive()` makes the resolver and the tree again only when the files changed.** A saved note changes neither.
- **The search table deletes by rowid.** Its `path` column is not indexed; a delete by path reads the whole table.
- **Work on many independent files or nodes is shared out with `concurrentPerform`**, each in its own slot of an `UnsafeMutableBufferPointer`, with the same order of operations, so the result is the same to the last bit. Deinitialize the buffer before it is deallocated, or what it holds leaks.

## Testing the app

The installed app comes from Homebrew only (`brew install --cask parham-alvani/tap/daftar`): a release (`VERSION` and a `v*` tag) reaches the tap's cask, and the cask installs it. Never copy a test build into `/Applications`; that makes the cask install fail and hides which version is installed. Test from `build/Daftar.app` (`just app`), with `open -n` and a test `XDG_CONFIG_HOME`; a build run from `build/` asks for notification permission again. The vault is the `vault` line of the config file. `open "daftar://open?path=Folder/Note.md"` opens a note, `daftar://open?path=today` the Today page, and `daftar://terminal` the terminal. A debug build makes the web view inspectable in Safari.

A Carbon hot key fires for a synthetic key only when the modifier keys go down first, as on a keyboard (`CGEvent` at `.cghidEventTap`); a key posted to the app's pid never reaches it.

**Do not click a task in the real vault to test.** A tick writes the file, and with automatic sync on, it commits and pushes. Test writes on a copy, or with the unit tests.
